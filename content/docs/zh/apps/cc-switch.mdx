CC Switch 是用来统一管理 AI 编程 CLI 的工具。你可以把 Claude Code、Codex CLI、Gemini CLI 等工具的 Provider、模型、API Key 放在一个地方管理，日常切换模型或切换接口时，不用反复改环境变量和配置文件。

<Callout type="info" title="什么时候优先用 CC Switch">
  如果你同时用 Claude Code 和 Codex CLI，或者经常在多个 API 地址、多个模型之间切换，优先推荐 CC Switch。只用单个工具、单个模型时，再看后面的 Claude Code 或 Codex CLI 手动配置教程。
</Callout>

## 适合谁用

| 用户 | 建议 |
| --- | --- |
| 只用 Cherry Studio 聊天 | 不需要 CC Switch，看 [Cherry Studio](/zh/docs/apps/cherry-studio) |
| 只用 Claude Code | 可以直接手动配置，也可以用 CC Switch 管理 |
| 同时用 Claude Code 和 Codex CLI | 优先用 CC Switch |
| 给团队成员发教程 | 优先写 CC Switch，减少每个人手动改配置出错 |

## 需要准备

| 配置项 | 填写值 |
| --- | --- |
| OpenAI 兼容 Base URL | `https://api.klong.lat/v1` |
| Claude 兼容 Base URL | `https://api.klong.lat` |
| API Key | `sk-your-api-key` |
| 聊天模型 | `gpt-5.4`；高质量可用 `gpt-5.5` 或 `claude-opus-4-7` |
| Codex 编程模型 | `gpt-5.5` |
| Claude Code 模型 | `claude-opus-4-7` |

## 它和手动配置有什么区别

| 方式 | 适合场景 | 缺点 |
| --- | --- | --- |
| CC Switch | 多工具、多模型、多 Key、多端点切换 | 需要额外安装一个管理工具 |
| 手动配置 Claude Code | 只用 Claude Code，配置固定 | 环境变量容易填错，换模型麻烦 |
| 手动配置 Codex CLI | 只用 Codex CLI，配置固定 | 需要自己维护 `config.toml` |

## 安装 CC Switch

### macOS

```bash
brew tap farion1231/ccswitch
brew install --cask cc-switch
```

### Windows

到 GitHub Releases 下载 `.msi` 安装包或便携版 `.zip`：

```txt
https://github.com/farion1231/cc-switch/releases
```

### Linux

到 GitHub Releases 下载 `.deb` 或 `.AppImage`。

Arch Linux 用户可以使用：

```bash
paru -S cc-switch-bin
```

## 配置小恐龙 API Provider

打开 CC Switch 后，新建一个 Provider，按你的目标工具选择配置方式。

### Claude Code

Claude Code 使用 Anthropic 兼容接口。Base URL 不要带 `/v1`。

| 字段 | 填写 |
| --- | --- |
| 应用 | Claude |
| 名称 | `小恐龙 Claude` |
| Base URL | `https://api.klong.lat` |
| API Key | 你的 `sk-...` |
| 主模型 | `claude-opus-4-7` |

### Codex CLI

Codex CLI 使用 OpenAI Responses API。Base URL 要带 `/v1`。

| 字段 | 填写 |
| --- | --- |
| 应用 | Codex |
| 名称 | `小恐龙 Codex` |
| Base URL | `https://api.klong.lat/v1` |
| API Key | 你的 `sk-...` |
| 主模型 | `gpt-5.5` |
| Wire API | `responses` |

## 推荐使用流程

<Steps>
  <Step title="先装目标 CLI">
    如果你要管理 Claude Code，先确保 `claude --version` 能正常返回；如果你要管理 Codex CLI，先确保 `codex --version` 能正常返回。
  </Step>
  <Step title="在 CC Switch 新建 Provider">
    按上面的表格填 Base URL、API Key 和模型名。Claude 和 Codex 的 Base URL 不一样，别混用。
  </Step>
  <Step title="切换到小恐龙 API 配置">
    在 CC Switch 中启用刚创建的 Provider，让它写入对应工具所需的配置。
  </Step>
  <Step title="打开终端验证">
    分别运行 `claude` 或 `codex`，发送一个简单任务，再到小恐龙 API 的使用记录里确认请求。
  </Step>
</Steps>

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| Claude Code 404 | Claude Base URL 通常填 `https://api.klong.lat`，不要加 `/v1` |
| Codex CLI 404 | Codex Base URL 通常填 `https://api.klong.lat/v1`，并使用 Responses API |
| 切换后没生效 | 关闭旧终端，重新打开终端再运行 CLI |
| 模型不可用 | 换成小恐龙 API 模型列表里真实存在的模型名 |
| 请求没出现在使用记录 | 确认当前 CLI 使用的是 CC Switch 切换后的 Provider |
